# Trained classifier: scope and design

The new workflow classifies **synthetic 64-number vectors** into three classes.
Each independently generated normal vector receives the label of the largest
sum among its first three blocks of eight features. The label is computed from
the vector, never from the chosen expert. Training, validation, and test sets
contain 600, 150, and 150 examples, generated by separately seeded streams.
The generator and labels are implemented in `neural_fabric/data.py`; this is
not evidence of real-world performance.

The router is a 64-to-3 linear layer. The experts are linear, 16-hidden-unit,
and 32-hidden-unit classifiers, each producing three logits. Soft mode runs
all experts on each input and combines logits using router probabilities.
Top-1 and top-k execute only experts selected for each sample, renormalize
selected weights, and combine their outputs. The final prediction is the
argmax of the softmax of the combined logits, not the router's selected index.

Training uses cross-entropy, Adam at 0.01, batches of 64, and validation loss
for checkpoint selection. The fixed small MLP is trained separately on the
same splits and epochs, with the same optimizer and batch order; initialization
and parameter budgets differ. Evaluation is exploratory: compare soft and
top-1 using the same checkpoint and fixed baseline; do not select a winner on
the test set and treat it as an unbiased claim. Repeat seeds by training
separate models with `--seed` and report per-seed paired differences.
To preserve a new evaluation, pass `--output path/to/new-result.json`;
the command refuses to overwrite an existing file. The parent directory must
already exist. The printed JSON remains available for scripting.

Checkpoint files include format and architecture versions, label mapping,
seed, configuration, validation loss, torch version and available Git commit.
The recorded commit is the checked-out HEAD at training time and does not
capture uncommitted changes. Loading uses PyTorch's `weights_only=True`;
only load checkpoints from trusted sources. CPU results may vary with PyTorch
version, platform and hardware; seeding does not promise cross-platform identity.

FLOPs are per sample: one multiply plus one add is two FLOPs. Router and
selected expert matrix operations are counted; bias, ReLU, softmax, masking,
dispatch, memory and Python overhead are excluded. Signed savings compare
against the separately trained fixed small MLP. Latency uses five warmups and
30 batch-one CPU model calls, reporting median and p95, excluding HTTP.
Latency is environment-dependent; no speedup is assumed.

The old `fabric/engine.py`, `backend/api/app.py`, and `frontend/index.html`
remain historical demonstrations with untrained weights. Their graph executes
in insertion order rather than as an edge-driven DAG, fusion and compute
semantics differ, and legacy FLOP savings exclude router overhead and clamp
negative values. Use `neural_fabric` for the new trained workflow.
Historical NF-02/NF-12 accuracy measures router mode classification, not the
accuracy of a prediction produced by experts. Old corrected and superseded
artifacts remain unchanged in `experiments/results/` and
`experiments/results_backup/`; see [RESULTS.md](RESULTS.md). Legacy
`attention` is a truncated projection, not genuine attention.

The separate agent loop can run commands, access files and network, and edit
the repository. Its string filters are not an OS security boundary. Do not run
it on untrusted objectives without independent isolation. It is not required
for training, inference or serving.

The local server is intended for development. It binds to 127.0.0.1 by default,
serves the UI from the same origin, does not emit CORS permission headers, and
has no authentication or TLS. Exposing it elsewhere requires network access
controls and authentication. Missing or incompatible checkpoints prevent
startup; prediction validation returns 400, oversized bodies return 413, and
unknown paths return 404. If model loading fails, confirm the checkpoint path
and regenerate it using the documented training command.
